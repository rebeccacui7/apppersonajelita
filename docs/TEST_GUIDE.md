# 测试数据与体验指南

## 1. 导入测试数据
前置：已导入 `schema.sql` + `seed.sql`，并已在宝塔拉取最新代码。

宝塔「终端」执行（把数据库名/用户名换成你的）：
```bash
mysql -u 数据库用户名 -p 数据库名 < /www/wwwroot/app.personajelita.com/database/testdata.sql
```
或在宝塔「数据库 → 管理(phpMyAdmin) → 导入」选择 `database/testdata.sql`。

- 可重复导入（会先清掉旧测试数据再重建），日期都相对导入当天生成
- 只用独立 ID 段，不影响你手工录入的数据
- 体验完清除：导入 `database/testdata_clear.sql`

## 4. 体验路线

### ① admin：全局总览（5 分钟）
1. **仪表盘**：KPI（在途签证/公司注册、待付供应商款等）、收支趋势、商机漏斗、执行业务概况；「7 天内到期的在途业务」「需跟进客户」中红色为已逾期
2. **客户列表** → 点「上海宏达物流」名称打开详情 → 切换 联系人 / 跟进 / 商机 / 应收 Tab，看客户 360
3. 任意列表试试：关键字搜索、下拉筛选、列头排序、底部**金额合计**、勾选批量删除、**导出** CSV
4. **系统管理 → 操作日志**：刚才的导出等操作都有记录

### ② sales01：销售日常 + 数据隔离
1. 登录后客户列表只看到**自己负责的 7 个客户**（数据范围=仅本人）；换 sales02 登录看到的是另一批
2. **跟进记录 → 新增**：客户选「南京智造装备集团」，填写下次跟进日期 → 回到客户列表，该客户的「下次跟进」已自动更新
3. **商机列表**：编辑「智造装备 MES」→ 阶段改为「赢单」，并把赢率清空 → 保存后赢率自动 100%、关闭日期自动填上，客户状态自动变为「已成交」
4. 再试把某商机改为「输单」但不填原因 → 会被拦截

### ③ pm01：签证 / 公司注册 → 供应商应付 → 完成项目（核心流程）
1. **执行管理 → 签证表**：只显示在途签证；**新增**一条：填业务群名、对接人、具体业务、申请对象、日期、供应商，「交付文件」处**上传附件**（可多选，PDF/图片/Office/压缩包）
2. 编辑「华晟矿业-印尼工签群 · 张伟」→ 办理状态改为「**已完成**」→ 保存，提示「已转入供应商应付」，**该记录从签证表消失**
3. **公司注册表** 同理（字段没有「申请对象」，状态叫「业务状态」）
4. 打开 **供应商应付**：刚完成的业务出现在这里，付款状态为「待付款」；pm01 只能查看，不能付款
5. 点交付文件的文件名可在线预览/下载

### ④ finance01：供应商付款
1. **供应商应付**：编辑一条记录，填「应付金额」→ 付款状态改为「**已付款**」→ 保存，提示「已转入完成项目」（付款日期留空默认今天）
2. 或直接点行上的「**标记已付款**」快捷按钮
3. 发现误操作：在应付表点「**退回在途**」回到签证/公司注册表（状态回到「办理中」）；在 **完成项目** 点「**撤回到应付**」回到待付款
4. **完成项目** 为只读归档：按业务类型/供应商筛选、按付款日期区间查询、导出 CSV
5. 供应商应付表不能直接「新增」——数据只能由业务完成后自动流入

### ⑤ finance01：财务闭环（应收 / 流水 / 报销）
1. **应收款**：筛选状态「未结清」，注意「二院 中期款」「Q3 运维费」已逾期
2. **收支流水 → 新增**：类型「收入」、类别「项目回款」、金额 194000、核销应收选「进度款 40%（宏达）」→ 保存后该应收自动变为「已结清」
3. 试着把核销应收的流水类型选成「支出」→ 被拦截
4. **费用报销**：对「待审批」单据点「通过」或「驳回」；「BXT003」已通过 → 点「**支付**」→ 自动生成一条支出流水
5. 「BXT008」是 finance01 自己提交的 → 审批会提示「不能审批自己提交的报销单」，需 admin 审批

### ⑥ buyer01：采购到应付
1. **采购订单**：「GPU 服务器 POT006」已下单 → 点「**生成应付**」→ 应付款列表出现新记录（再点一次会提示已生成）
2. 新增采购单，供应商选「黑石外包服务」→ 被拦截（黑名单）
3. 供应商「华信服务器」→ 删除 → 提示有采购单不能删除

### ⑦ admin：权限管理
1. **角色权限** → 「销售」行点「分配权限」→ 取消勾选「客户列表 → 删除」→ 保存
2. 用 sales01 刷新客户列表 → 「删除」按钮消失，且接口层也会拒绝（权限实时生效）
3. **用户管理** → 把 sales02 状态改为停用 → sales02 立即被踢出登录
4. **部门管理**：删除有成员的「销售部」→ 被拦截

- 修改 admin 密码；正式使用前确认没有遗留测试账号
